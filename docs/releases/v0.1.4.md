# RSVP Nano v0.1.4 — updates from older firmware

This Classic maintenance release restores on-device updates for older LCD 3.49
firmware that reports **rsvp-nano-ota.bin missing** (or the Rev2 equivalent).
Classic remains the stable/default interface. New UI v0.2.0 remains an optional
preview for LCD 3.49 Rev1.

## Updating an older Nano

Run the normal firmware update again using the official `ionutdecebal/rsvpnano`
source. Older devices can discover the compatibility OTA files and install
Classic v0.1.4. On LCD 3.49 Rev1, **Try New UI** then offers v0.2.0.
LCD 3.49 Rev2 and the other supported boards continue using Classic.

If you use the browser installer, select your exact board revision and leave
**Erase first off**. For manual downloads, extract the matching full `.bin` from
`rsvp-nano-browser-installers.zip`. The individual `-ota.bin` files are only for
on-device OTA; they are not full browser-flash images.

## What was fixed

- Restored `rsvp-nano-ota.bin` for LCD 3.49 Rev1 and
  `rsvp-nano-rev2-ota.bin` for LCD 3.49 Rev2. Each is an exact copy of its
  board-specific application-only image. These names were removed in v0.0.9,
  while firmware through v0.0.8 still requests them.
- Bundled the nine full browser-flash images into one ZIP. Older firmware reads
  only the first 32768 bytes of GitHub release metadata; publishing every browser
  image separately would push the restored filenames beyond that limit.
- Added release checks for both legacy filenames, matching image digests and
  discovery within the old metadata limit. Browser staging verifies the ZIP and
  each board image against the published checksums.

The reader and device firmware code is unchanged from Classic v0.1.3; this release
is rebuilt with the v0.1.4 identity. It retains the Rev1 interface selector. Existing
v0.1.3 and v0.2.0 downloads and tags remain available unchanged.

## Validation

Packaging, checksum rejection, legacy metadata boundaries and the browser staging
path have automated tests. Actual v0.0.8 LCD Rev1/Rev2 partition tables were compared
with v0.1.3 and match; both OTA images fit the existing slots. All nine release
targets are built. GitHub metadata is checked before publication and again publicly.

The founder already confirmed on-device switching between v0.1.3 and v0.2.0.
An actual older-device update to v0.1.4 still needs community/device confirmation;
host checks do not establish a completed physical update or power-loss recovery.
