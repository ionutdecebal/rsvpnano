# RSVP Nano v0.1.3 — Classic update choice

Classic remains the stable/default interface. This maintenance release adds a
confirmed way to try the optional New UI on **LCD 3.49 Rev1**, alongside normal
Classic updates. All existing board firmware downloads remain included.

## Changes

- On LCD 3.49 Rev1, Firmware updates checks Classic or **Try New UI**, displays the
  selected release and waits for confirmation before installation.
- Normal updates stay on the selected interface. Explicit switching uses the official
  update catalog, retaining a backup of any advanced update-source override in NVS.
- Verified HTTPS streaming checks exact size and SHA-256, writes the inactive app slot
  and saves switching settings before selecting the new boot slot.
- New UI chunk settings are accepted as single-word RSVP when returning to Classic.
- Other boards keep their existing release-based update path and Classic interface;
  New UI 0.2.0 is only offered for LCD 3.49 Rev1.

## Install and return

Use the [web companion](https://ionutdecebal.github.io/rsvpnano/) and choose Classic
for your exact board revision. Use merged `.bin` files in the browser installer;
`-ota.bin` files are application-only OTA images. Leave **Erase first off**.

Back up the SD, including settings and reading progress. The library layout is
unchanged, but Classic can replace preferences specific to the New UI when saving.
Books, recordings and deferred ecosystem data are not deleted.

## Validation

The founder confirmed the preceding Rev1 candidate's browser-flashed Classic/New UI
round trip. Shared settings codecs and update failure ordering passed local tests.
Final release images are rebuilt with the v0.1.3 identity. The other board builds are
compile-checked; this is not a claim of new physical validation on every board.
Real Wi-Fi OTA round-trip testing remains separate from browser-flash compatibility.
